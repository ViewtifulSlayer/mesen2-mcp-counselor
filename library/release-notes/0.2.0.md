# Counselor Library 0.2.0

A game-context library for [Mesen2 MCP](https://github.com/Azarem/mesen2-mcp). The
emulator and MCP server are unchanged; this release adds the first PC/Unity pack
and makes the additive `target` and `harness` contract part of the public
authoring surface. Existing GB and SNES packs validate unchanged.

This is a fork of Azarem's server and follows its `0.6.0` behavior. The library is
additive and can be copied into any existing `mesen2-mcp` checkout.

| Build | Unity 2019.4.16f1, IL2CPP metadata v24 |
| Pack version | 0.1.0 |
| Status | verified |

The third pack targets save-tool and data-mapping work rather than a playthrough.
It gives an agent:

- The `SaveData.bin` contract: a raw DEFLATE stream whose payload is JSON, with
  the inner slot state stored as a JSON string inside
  `saveDataList[n].saveDataJsonStr`.
- Six reference pages (`overview`, `world`, `systems`, `data`, `harness`, and
  `edge-cases`) plus US, JP, and PS1/Remastered variant notes.
- Six derived tables: the save field map, sentinels, ID namespaces, build
  identity, known gaps, and the table inventory. The table inventory accounts
  for the 11 runtime tables and their source datasets.
- `harness/save_lab.py`: stdlib-only raw DEFLATE inflate/deflate, nested JSON
  diff, and Asellus/T260G fixture assertions. The field test records `20/20` and
  `33/33` checks passing; the diff helper reaches the inner slot fields.
- A build identity made of six measured file hashes, so a different install can
  be distinguished instead of silently inheriting the map.

The pack is verified, not certified. `world`, `systems`, `harness`, and
`variants` are partial, and no rubric score is claimed. The integrity fields
(`sfSys.chk*`, `sum`, `pty.sum`) are not understood. INIT 3 (BR 4-6) has not been
observed, the last-clear rank field is not identified, current-area versus
scenario-start area is not distinguished by the fixtures, and 343 `snroFlg`
bytes are unnamed. The [BepInEx 6](https://github.com/BepInEx/BepInEx) IL2CPP
runtime bridge is specified but not implemented, which is why `harness` remains
partial.

## The additive PC/Unity contract

The additive schema extension adds `platform: "pc"` with a `target` object for
build identity instead of the ROM block. A `target` records the Unity version,
scripting backend, metadata version, and measured file hashes. A `harness`
object declares the runtime kind, scripts, recipes, and notes. `lua` remains
optional for harness packs, and `tested.harness` records what the field test
actually ran.

The change is additive:

- GB and SNES packs keep their existing `rom`, `mesen2Mcp`, and `lua` blocks.
- `install_pack.py` recognizes a harness pack and prints the harness reference
  instead of an `--mcp-lib-dir` value.
- `check_tree.py` checks declared harness scripts as part of the pack layout.
- `.bin` is now in the forbidden-extension guard, so a save file cannot enter a
  pack or a release bundle.

The academy, installer, rubric, checklists, and release documentation now
describe both cartridge and harness packs.

## The authoring bundle now has three packs

`counselor-authoring-v0.2.0.zip` ships the Academy, schemas, tools, permissions,
template, and all three packs as worked examples. The 0.1.0 bundle contained only
Final Fantasy Legend and Secret of the Stars; 0.2.0 adds SaGa Frontier Remastered
so authors can see the PC/Unity `target` and `harness` shape alongside the
cartridge packs.

The authoring archive has **141 content files**, up from 116 in 0.1.0, including
**25** from the PC pack. Regression tests now assert that every pack's
`pack.json` and `SKILL.md` are in that archive, and that every pack has its own
installable archive with both files at the root. Negative tests remove a pack
include and a per-pack entry and confirm both guards report the gap. The release
`--check` path enforces both directions of the per-pack mapping before inspecting
the archives: every shipped pack needs a bundle entry, every `pack:*` entry needs
a pack directory, and each entry's include patterns must select that pack's
`pack.json`. The pack archives are still the installable unit; the authoring
bundle is a reference and teaching surface.

cannot enter them, and the test suite is not shipped.

## Install

For the new pack:

```bash
python library/tools/install_pack.py --pack pc/saga-frontier-remastered --target .agents/skills
```

No Lua kit and no `--mcp-lib-dir` are needed. The pack installs as
`.agents/skills/sfr-save-mapping/`, and the save lab runs from the installed pack
or the repository. Restart the client so the skill list reloads.

The cartridge path is unchanged:

```bash
python library/tools/install_pack.py --pack gb/final-fantasy-legend --target .agents/skills
```

The tools need Python 3 and `library/tools/requirements.txt`; the server needs
.NET 8 and Mesen2 MCP 0.6.0.

## Upgrade from 0.1.0

Copy the new `library/` over the old one. The GB and SNES pack source files need
no migration, and the new pack is additive. If you install a pack as a skill,
reinstall it after upgrading so the client reloads the skill. The authoring
bundle is the one that changes shape: it now contains three packs instead of two.

## Known limits

- SaGa Frontier Remastered is verified against local Asellus and T260G fixtures,
  not a live-game field test. The runtime bridge is a plan.
- Final Fantasy Legend and Secret of the Stars carry the same limits as 0.1.0.
  Secret of the Stars still has no walked entrance to the Ancient Well; Final
  Fantasy Legend's region variants are still an outline.
- No pack claims a JP field test yet.
